### 1.3 模块插入位置

MambaCue 解码器的特征尺度（实测）：

| 位置 | 形状（256 输入） | 相对分辨率 |
|---|---|---|
| `decoder.dec3` 输出 | `[B, 128, 64, 64]` | **1/4** ← 插入点 |
| `decoder.dec2` 输出 | `[B, 64, 128, 128]` | 1/2 |
| `decoder.dec1` 输出 | `[B, 32, 256, 256]` | 1× |

按原文 §2.2「骨干解码器的 1/4 分辨率特征处加入模块」，插入点选
**`decoder.dec3` 的输出**，通过 `decoder.dec2` 的 `forward_pre_hook` 改写 `args[0]`。
骨干其余部分（prior 融合、color_correction、detail_inject、输出头）**零改动**。

选择 pre-hook 而非改源码的理由：不修改第三方仓库，且已单独验证梯度能正确穿过 hook
（模块参数在 hook 下游收到的梯度与直接前向一致）。

### 1.4 四个配置的精确定义

记 `C=128`（dec3 输出通道），`F` 为 dec3 输出。

**E0 — 原骨干继续训练**

```
F' = F        新增参数 0
```

作用：测出「单纯多训练」能带来多少收益。

**E1 — 普通残差容量（参数量对齐 E2）**

```
F' = F + W_out( R_K(F) )
R(x) = x + Conv1x1( SiLU( DWConv3x3(x) ) )
```

K 由 `match_blocks_to_budget` 自动取到「新增参数 ≥ E2」的最小整数，实测 **K=10**。
`W_out` 为 1×1 卷积、零初始化。

**E2 — 局部 + 上下文双路径，固定 0.5/0.5 融合**

```
F_o = L(F)                              局部路径
F_c = C(F)                              上下文路径
F'  = F + W_out( 0.5·F_o + 0.5·F_c )
```

- **局部路径 L**：两个轻量残差块，每块 = `DWConv3x3 → SiLU → Conv1x1`，带残差。
- **上下文路径 C**：`F` → Query；`F` 自适应池化到 8×8 → Key/Value；
  4 头交叉注意力（`d_head = C/4 = 32`）；再做 `Conv1x1` 通道混合 + 残差。
  所有位置都能读全局信息，代价是 `O(HW·64)` 而非全分辨率自注意力的 `O((HW)²)`。
- `W_out`：1×1 卷积，零初始化。

8×8 与 4 头是原文规定的首轮配置，**未做超参搜索**。

**E3 — E2 + 空间—通道可学习融合**

```
F_o = L(F);  F_c = C(F)
G   = sigmoid( Q([F, F_o, F_c]) )
F'  = F + W_out( G ⊙ F_o + (1−G) ⊙ F_c )
```

`Q`：拼接（3C 通道）→ 1×1 降维到 C → 3×3 深度卷积 → 1×1 输出 C 通道。
最后一层卷积的**权重与偏置都零初始化**，使初始 `G ≡ 0.5`，与 E2 的初值一致。

### 1.7 训练协议（四个 arm 完全一致）

| 项目 | 取值 |
|---|---|
| 输入 | 整图缩放到 256×256，PIL BILINEAR，不裁剪、不填充、不保持长宽比 |
| batch | 8，梯度累积 2 → **有效 batch 16** |
| 优化器 | AdamW，betas (0.9, 0.999)，weight_decay 1e-4 |
| 学习率 | 骨干 **1e-5**，新增模块 **1e-4**（分参数组） |
| 调度 | 300 次更新线性 warmup + cosine 降至 1e-6 |
| 梯度裁剪 | max_norm = 1.0 |
| 混合精度 | **不用 AMP**（mamba_ssm 1.1.1 的 selective-scan 在 autocast 下不稳定） |
| 损失 | MambaCue 源码 `UPSNetLoss`，**未做任何修改** |
| 更新步数 | 10 000（有效样本 20 000） |
| 验证频率 | 每 500 次更新 |
| 数据增强 | 随机水平/垂直翻转，**对输入与 GT 同步施加** |
| 随机种子 | 0 |
| 选模 | 按 `PSNR + 10·SSIM`（沿用 MambaCue 原配方） |

**损失函数的确切形式**（`/home/user/MambaCue/utils/loss_funcs.py`）：

```
total = 1.0·Charbonnier + 0.5·SSIM + 0.1·Perceptual(VGG19) + 0.2·Lab + 0.1·Gradient
```

注意 `w_angle·loss_angle` 那一行在源码中**处于注释状态**，本轮按源码执行，不加 Angle 项。

### 1.8 评测协议（冻结，与仓库既有实现逐位一致）

1. 整图 → 256×256，PIL `Image.BILINEAR`；
2. PSNR：float `[0,1]`，`data_range=1.0`；
3. SSIM：`skimage.metrics.structural_similarity(channel_axis=-1, win_size=5, data_range=1.0)`；
4. **先逐图计算，再算术平均**；每张图都计入，不剔除。

我重写的 scorer（`code/obsui/ablate_eval.py`）与仓库权威实现
`run_baseline.score` 做过**逐位一致校验**：12 组合成图像上 `max|Δ| = 0.0`。
这是允许用新 scorer 报告数字的唯一依据。

### 1.9 判定标准（照抄原文 §3）

- E1 比 E0 有收益，E2/E3 无进一步收益 → 保留普通残差，继续优化训练
- E2 比 E1 有收益，E3 无收益 → 采用固定融合，去掉门控
- E3 超过 E2 → 保留可学习融合，进入 E4
- 全部新结构无增益 → 不扩大模型；先查梯度/学习率/是否未收敛，再把位置从 1/4 改到 1/8

收益量级参考：**+0.15–0.30 dB PSNR 或 +0.002 SSIM** 视为值得继续的信号。

统计上额外要求：逐图配对 bootstrap（10 000 次，按图重采样）的 95 % CI
**不含 0**；CI 含 0 的点估计一律记为「未建立」。

### 1.10 两个基线的区分（关键设计）

因为起点权重本身是在**同一个 val** 上按 `PSNR+10·SSIM` 选出的最优 checkpoint
（`records.txt` 的 best epoch 记录可查），"继续训练必然先降后升"。所以每个结果都给两个基线：

| 基线 | 回答的问题 | 判据 |
|---|---|---|
| **相对 E0** | 模块本身有没有用（消除"继续训练"这个共同变量） | 主要判据 |
| **相对起点** | 有没有真的超过已发布权重 | 决定能否对外声明提升 |

**只有两者同时为正，才构成"模块带来实际提升"。**
只有相对 E0 为正、相对起点为负的，只能写成"减缓了继续训练的退化"。

| 亮度 brightness | −0.337 | −0.434 | −0.493 |
| 对比度 contrast | −0.853 | −0.279 | −0.126 |
| 细节 detail | −0.679 | −0.493 | −0.094 |

**读法**：12 个分层格里，**没有一个格是正收益**。
最接近零的是 E1 在"低色偏"层（−0.006，60 % 图改善），在噪声范围内。
**不存在"某个退化类别上双路结构占优"的情况**——这条常见的辩护不成立。

### 2.7 训练损失 vs 验证指标（方向相反）

| 实验 | 末尾 train loss（PSNR+10·SSIM 口径的 score） | val PSNR | test PSNR |
|---|---:|---:|---:|
| E0 | 32.4361 | 23.3506 | 23.8572 |
| E1 | 32.1356 | 23.0706 | 23.6563 |
| E2 | 32.2113 | 23.1390 | 23.5938 |
| E3 | 32.0669 | 23.0100 | 23.4359 |

训练损失排序 E3 < E1 < E2 < E0，验证指标排序正好相反。
**新模块确实在优化训练目标，只是朝过拟合的方向优化。**

### 2.8 分支与门控诊断（回应原文 §2.3「某一路是否长期不学习」）

在固定 probe batch 上测的 `delta_norm`（模块输出增量的范数）与门控统计：

| 配置 | 指标 | 更新 0 | 更新 5000 | 更新 9999 |
|---|---|---:|---:|---:|
| E1 | delta_norm | 0.008 | 98.10 | 109.10 |
| E2 | delta_norm | 0.004 | 166.34 | 101.60 |
| E2 | local_norm | 391.66 | 464.40 | 454.33 |
| E2 | context_norm | 371.95 | 868.59 | 514.21 |
| E3 | delta_norm | 0.004 | 238.88 | 126.64 |
| E3 | gate_mean | 0.5000 | 0.4386 | **0.3303** |
| E3 | gate_std | 0.0000 | 0.2395 | 0.1915 |
| E3 | gate_min | 0.5000 | 0.0001 | 0.0002 |
| E3 | gate_max | 0.5000 | 1.0000 | 0.9609 |

**三条结论**：
1. **梯度通畅**：增量范数从 0.004 涨到 100+，两条路径都在更新，
   不存在"某一路长期不学习"的问题（这是原文 §2.3 要求排查的第一项）。
2. **门控单调偏向局部路径**：E3 的 `gate_mean` 从 0.5 → 0.44 → 0.33，
   `gate_min` 掉到 0.0002。网络学到的是"优先用局部信息、少用上下文"，
   正好与"上下文补偿有价值"的假设相反。
3. 上下文路径的范数在 5000 步时冲到 868，远高于局部路径的 464，
   但到 9999 步又落回 514——说明它在剧烈震荡，没有稳定学到有用的全局信息。

### 2.9 UIEB 上的补充观察：起点已是最优

起点权重本身就是按 `PSNR + 10·SSIM` 在同一 val 上挑出的最优 checkpoint。
1500 步预跑与 10 000 步正式跑的对照：

| 更新步 | val PSNR（预跑 1500） | val PSNR（正式 10 000，E0） |
|---:|---:|---:|
| 0 | 23.8255 | 23.8255 |
| 150 / 500 | 23.7612 | 23.7294 |
| 300 / 1000 | 23.7747 | 23.6538 |
| 450 / 1500 | 23.7819 | 23.5791 |
| 600 / 2000 | 23.7340 | 23.5888 |
| 750 / 2500 | 23.7327 | 23.4737 |
| 900 / 3000 | 23.6931 | 23.5253 |
| 1050 / 3500 | 23.7041 | 23.4925 |
| 1200 / 4000 | 23.6997 | 23.4533 |

预跑看到的"先降后回升"在 10 000 步尺度上**没有兑现**：整体是持续下降。
这说明起点权重处在一个很窄的局部最优上，用骨干 1e-6~1e-5 的学习率继续训练
就是单纯地往外走。

**已排除实现错误**：单步优化（骨干 1e-6 / 新模块 1e-5 / 两者）对 val 只造成
±0.0008 dB 的变动，一步不可能产生这种漂移；这是训练的累积效应，不是 bug。
另做过一次分组消融：只更新骨干、只更新新模块、两者同时更新，三者单步影响都在
±0.001 dB 内。

## 附：一句话总结当前状态

**UIEB 上四个配置全部失败**：没有一组超过已发布权重，也没有一组超过"什么都不加、

**LSUI 的结果可能改变这个判断**——它的 E0 曲线与 UIEB 形态完全不同（持平 vs 持续下降），
必须等 LSUI 的 E1–E3 才能确定 UIEB 的退化有多少是小验证集噪声。
