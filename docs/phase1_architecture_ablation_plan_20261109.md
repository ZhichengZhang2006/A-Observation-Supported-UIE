## 3. 模块插入位置

MambaCue 解码器的特征尺度（实测）：

| 位置 | 形状 | 相对分辨率 |
|---|---|---|
| `decoder.dec3` 输出 | `[B, 128, 64, 64]` | **1/4**（256 输入） |
| `decoder.dec2` 输出 | `[B, 64, 128, 128]` | 1/2 |
| `decoder.dec1` 输出 | `[B, 32, 256, 256]` | 1× |

按原文 §2.2「骨干解码器的 1/4 分辨率特征处加入模块」，
插入点 = **`decoder.dec3` 的输出 `F ∈ R^{B×128×64×64}`**，模块输出
`F' = F + Δ`，其余骨干（prior 融合、color_correction、detail_inject、
输出头）完全不动。

## 4. 四个配置的精确定义

记通道数 `C=128`（即 dec3 输出通道），`F` 为 dec3 输出。

### E0 — 原骨干继续训练

无新增参数。`F' = F`。目的：测出「单纯多训练」能带来多少提升。

### E1 — 普通残差模块（容量对齐）

`F' = F + W_out(R_K(F))`，`R` 为普通轻量残差块：

```
R(x) = x + Conv1x1( SiLU( DWConv3x3(x) ) )
```

`K` 取到与 E2 新增参数量匹配（不预设 K，代码里按参数量自动定，取 K 使
总新增参数落在 E2 的 ±10 % 内）。`W_out` 为 1×1 卷积、**零初始化**。

这一组回答原文 §2.4 的问题：「同等规模的普通残差模块是否已经取得全部收益」。

### E2 — 局部 + 上下文双路径，固定 0.5/0.5 融合

```
F_o = L(F)          # 局部路径
F_c = C(F)          # 上下文路径
F'  = F + W_out( 0.5 * F_o + 0.5 * F_c )
```

- **局部路径 L**：两个轻量残差块，每个 = `DWConv3x3 → SiLU → Conv1x1`，带残差。
  提供边缘、纹理、局部颜色。
- **上下文路径 C**：`F` → Query；`F` 自适应池化到 8×8 → Key/Value；
  4 头交叉注意力（`d_head = C/4`）；再做 `Conv1x1` 通道混合 + 残差。
  所有空间位置都能读全局信息，避免全分辨率自注意力开销。
- `W_out`：1×1 卷积，零初始化。

8×8、4 头是原文规定的首轮配置，不做超参搜索。

### E3 — E2 + 空间—通道可学习融合

```
F_o = L(F);  F_c = C(F)
G   = sigmoid( Q([F, F_o, F_c]) )
F'  = F + W_out( G ⊙ F_o + (1-G) ⊙ F_c )
```

`Q`：拼接（3C 通道）→ 1×1 降维到 C → 3×3 深度卷积 → 1×1 输出 C 通道。
`G` 与 `F` 同形状 `[B, C, H, W]`，同时按空间和通道选择。
门控最后一层卷积 **偏置与权重都初始化为 0**，使初始 `G ≡ 0.5`，与 E2 初值一致。

因果链：E0 ⊂ E1 ⊂ E2 ⊂ E3，逐层只加一个变量。

### 4.1 实现后的实测参数量（回填，替换开工时的预估）

| 配置 | 新增参数 | 相对 E2 | 说明 |
|---|---:|---:|---|
| E0 | 0 | −100 % | 恒等 |
| E1 | 194 432 | **+5.6 %** | K=10 个普通残差块 + 1×1 输出 |
| E2 | 184 192 | — | 局部 L + 上下文 C + 1×1 输出 |
| E3 | 251 264 | +36.4 % | E2 + 融合门 Q（3C→C 降维 + DW3x3 + 1×1） |

骨干 2 244 946 参数。E1 的 K 由 `match_blocks_to_budget` 自动取到 ≥ E2 参数的
最小 K，实测 K=10 时 +5.6 %，落在 §4 约定的 ±10 % 内。
E3 比 E2 多出的 36 % 是融合门本身，属于该 arm 定义的一部分，不是额外变量。

### 4.2 因果链的严格性

| 对照 | 只改变了 | 没改变 |
|---|---|---|
| E0 → E1 | 有没有额外残差容量 | 训练步数、损失、数据、种子 |
| E1 → E2 | 容量是否组织成「局部 + 上下文」双路 | 参数量级（+5.6 % 内）、其它全部 |
| E2 → E3 | 双路融合是否可学习 | 双路本身、其它全部 |

E1 → E2 的参数量差（5.6 %）是本轮唯一没能完全消除的混淆项，
已在结果表与风险评估里写明。

## 6. 评价指标

主指标（原文 §3）：平均 PSNR、平均 SSIM（skimage win5，256×256 统一协议）。

辅助指标（原文 §3、§8 要求）：

1. **逐图增益分布**：每张 val 图的 ΔPSNR / ΔSSIM 相对 E0，输出中位数、均值、
   25/75 分位、以及 ΔPSNR > 0 的图占比；
2. **强色偏 / 低亮度 / 低对比度 / 细节区域分层**：用输入图的客观统计量分层
   （饱和度偏离、平均亮度、局部对比度、梯度能量各取三分位），逐层看 ΔPSNR；
3. **学习曲线**：每 500 次更新在固定 val 上评一次，落盘完整曲线；
4. **训练速度与显存**：每步耗时（s/iter）、峰值显存（GB）；
5. 逐图 PSNR/SSIM 全量落盘（CSV），不只给均值。

诊断项（只在需要时跑，不作为门槛）：两分支梯度范数、门控 `G` 的分布
（E3）、输出增量 `Δ` 的范数。原文 §2.3 要求记录这些以防「某一路长期不学习」。

## 8. 判定标准（照抄原文 §3「首轮判断规则」）

- E1 比 E0 有收益，E2/E3 无进一步收益 → 保留普通残差，继续优化训练。
- E2 比 E1 有收益，E3 无收益 → 采用固定融合，暂时去掉门控。
- E3 超过 E2 → 保留可学习融合，进入 E4。
- E4 无适用（本轮不做）。
- 全部新结构无增益 → 不扩大模型；先查梯度/学习率/是否未收敛，
  再把插入位置从 1/4 改到 1/8 做一次实验。

**收益的量级参考（原文 §3）**：+0.15–0.30 dB PSNR 或 +0.002 左右 SSIM
视为值得继续投入的信号，需结合另一指标；这是筛选参考，不是承诺或硬门槛。

**统计判定（补充，不替换上面的规则）**：对 E1/E2/E3 相对 E0 的逐图 ΔPSNR
做配对 bootstrap（10 000 次重采样，按图重采样），给出 95 % CI。
若 CI 含 0，即使点估计为正也按「无稳定收益」处理，并在报告里写明。

## 10. 预期结果

先说结论方向，避免事后解释：

- **最可能**：E1 ≈ E0（多训练带来的提升被普通残差容量重复实现），
  E2/E3 的 ΔPSNR 落在 ±0.1 dB 以内，即**无显著结构收益**。
  这与上一阶段「支撑度量不能转化为增益」的负面结果一致。
- **次要可能**：E1 有 +0.1 dB 左右的收益（因为新增模块本身有效），
  E2/E3 相对 E1 无进一步收益 → 按判定规则保留普通残差。
- **若有真实增益**：应表现为 E2 相对 E1 的 ΔPSNR 稳定为正且 bootstrap CI 不含 0，
  且 E3 相对 E2 再有小幅提升。这时才进入 E4。

不以「某配置训练曲线早期更低」判负——原文 §3 明确要求前两名延长训练，
任何配置在 10 000 步内仍在明显上升的，延长到 20 000 步再判。

## 11. 已知风险与偏差

1. **起点权重已被这个 val 选过 —— 这是本轮最重要的偏差**。
   发布的 MambaCue 权重本身就是按 `psnr + 10*ssim` 在同一 val 上挑出的最优
   checkpoint（`records.txt` 里 best epoch 的记录可查）。因此「以它为起点继续训练」
   必然先降后升。1500 步实测（seed 0，UIEB，E0）：

   | 更新步 | val PSNR | val SSIM |
   |---:|---:|---:|
   | 0（起点） | 23.8255 | 0.912363 |
   | 150 | 23.7612 | 0.912118 |
   | 300 | 23.7747 | 0.912046 |
   | 450 | 23.7819 | 0.911650 |
   | 600 | 23.7340 | 0.911633 |
   | 750 | 23.7327 | 0.911302 |
   | 900 | 23.6931 | 0.911375 |
   | 1050 | 23.7041 | 0.911254 |
   | 1200 | 23.6997 | 0.911171 |

   已排除实现错误：单步优化（骨干 1e-6 / 新模块 1e-5 / 两者）对 val 的影响是
   ±0.0008 dB，即一步不会造成这种漂移；漂移是微调本身的累积效应。

   **处理方式（已与你确认，2026-11-09）**：照原方案跑 E0–E3，但每个结果都给两个基线：
   - **相对 E0**：回答「模块本身有没有用」（消除「继续训练」这个共同变量）；
   - **相对起点**：回答「有没有真的超过已发布权重」。
   两者必须同时为正，才能说模块带来了实际提升；只有相对 E0 为正而相对起点为负的，
   结论只能写成「减缓了继续训练的退化」，不能写成提升。

2. **划分污染**：LSUI 有 train∩val=12、train∩test=10、val∩test=2 的内容重复，
   约 2–3 %。会同时抬高 E0 与 E1–E3，对**差值**影响很小但不为零。
   报告里对 LSUI 额外给出剔除重复图后的均值。
3. **单 seed**：任何 < 0.05 dB 的差值都在噪声内，不可解读。
4. **学习率未调**：新增模块 1e-4 是原文给定的初值。若 E2/E3 明显欠拟合，
   按原文 §3 的兜底规则先查梯度再决定，不先调。
5. **E1 的容量对齐是近似的**：E1 比 E2 多 5.6 % 参数（194 432 vs 184 192），
   「参数相近」不等于「容量相同」。E3 比 E2 多 36 %（251 264）。
   三个 arm 的参数量在结果表里明写。
6. **1/4 位置的单点测试**：本轮只测一个插入位置，1/8 是原文明说的兜底而非首轮。
7. **AMP 未启用**：比长跑慢约 1.5–2×，但避免了 mamba_ssm selective-scan 的精度问题。
8. **损失函数版本**：按你的指示直接使用 `/home/user/MambaCue/utils/loss_funcs.py`
   当前源码，即 `charb + ssim + percep + lab + grad`（`w_angle*loss_angle` 那行是
   注释状态）。注意这与起始权重目录名 `...+Angle` 不一致；由于 E0–E3 四组用的是
   同一个损失，**组间比较不受影响**，但「相对起点」的差值会混入损失变化。
   这一点在选择「相对 E0」作为主判定时已规避。

## 12. 开工前已确认的四个问题（2026-11-09）

1. **损失**：**直接使用 MambaCue 源码的 UPSNetLoss**，即
   `charb + ssim + percep + lab + grad`（`w_angle*loss_angle` 保持注释状态）。
   你另行要求的「自适应权重损失」作为**独立的 L 阶段**，接在胜出结构上再跑，
   不并入 E0–E3，以免混入被 §6 明确要求隔离的变量。
   —— 已按此实现：`train_ablation.py` 直接 `from utils.loss_funcs import UPSNetLoss`，
   不做任何包装或改系数。
2. **步数**：四组统一 **10 000 次更新**（有效 batch 16），然后把每个数据集的前两名
   延长到 **20 000 次**。
3. **划分**：val 选模；**val 与 test 都报**，test 作主表并明确标注「历史分析已检查过，
   非密封集」。
4. **E1 形态**：按参数量对齐的普通残差块堆叠（`DW3x3→SiLU→Conv1x1` 残差 ×K
   + 零初始化 1×1 输出），K 由参数量自动定；实测 K=10、比 E2 多 5.6 %。
